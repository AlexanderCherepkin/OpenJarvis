# AGENTS.md — Инженерный регламент C:/OpenJarvis

## Environment & Tool Rules (Windows / LM Studio 12B)
- Все пути к файлам передавать в Windows-формате с буквой диска (`C:/OpenJarvis/...`), не использовать `/c/...` внутри инструментов `file_read`/`file_write`.
- Запрещено выдавать код файлов только в ответе: каждый целевой файл должен быть создан через `file_write` и проверен через `file_read` или запуск тестов.
- Рабочая песочница для новых проектов: `C:/OpenJarvis/workspace/<project_name>/`.

## Workflows
1. **Продуктовая постановка (PRD):** Для новых сервисов сначала зафиксировать требования и критерии приёмки в `C:/OpenJarvis/docs/plans/<feature>-prd.md` (`prd-workflow`), разделяя односессионные задачи (`prd-to-plan`) и многосессионные проекты (`prd-to-issues`).
2. **Техническое проектирование и план:** Перед кодингом провести декомпозицию на шаги по 2–5 минут (`brainstorming` → `writing-plans`) с фиксацией контрактов API и схемы БД.
3. **Разработка и проверка:** Реализовывать через цикл `test-driven-development` (`RED -> GREEN -> REFACTOR`), удерживать минимальный дифф (`ponytail`) и закрывать задачу только после фактического прохождения тестов (`verification-before-completion`).
4. **Проектная память:** Архитектурные решения (`decision`) и неочевидные ошибки среды (`gotcha`) фиксировать через `claudemem --project C:/OpenJarvis`.
